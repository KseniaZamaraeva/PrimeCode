## **1. ВХІДНІ СПЕЦИФІКАЦІЇ**

Розділ «Вхідні специфікації» регламентує **входи**, необхідні для проходження всіх тестів для даного рішення. У числі таких входів можуть бути дані, введені з клавіатури, натиснення кнопок миші у відповідних місцях сторінки, датчики, комп'ютерне та інше обладнання, різні дії користувачів. 

Опис специфікацій поряд з найменуванням входу містить його *характеристики*, такі як значення (що введено), структури даних (якого типу), інтерфейси (яким чином), протоколи, бази даних, файли тощо.

:point_right: Наведіть вхідні специфікації. Ви можете зробити це у вигляді тексту або таблиці.

## **2. ВИХІДНІ СПЕЦИФІКАЦІЇ**

Розділ «Вихідні специфікації» регламентує **виходи**, очікувані як результат проходження тестів для вашого рішення. Виходи можуть містити дані, інформацію про час виконання операцій, повідомлення, логи, дампи пам'яті, файли, знімки екрану тощо. 

:point_right: Наведіть тут вихідні специфікації.

## **3. СЕРЕДОВИЩЕ ТЕСТУВАННЯ**

У цьому розділі описуються *характеристики і конфігурація середовища* тестування. Такий опис може включати апаратуру, програмне оточення, інструменти, спеціалізоване програмне забезпечення тощо.

:point_right: Опишіть тут апаратне і програмне забезпечення (ОС, браузери тощо), необхідне для виконання тестів, програмне забезпечення з допомогою якого будуть виконуватись тести, потрібні налаштування тощо.  

**Середовище тестування**

 У цьому розділі описуються характеристики та конфігурація середовища тестування, включаючи апаратне та програмне забезпечення, необхідне для виконання тестів, а також інструменти для тестування та їхні налаштування.

**Апаратне забезпечення**

   Для коректного виконання тестів необхідні такі апаратні ресурси:

  - Процесор: Intel Core i7 / AMD Ryzen 7 або вище

  - Оперативна пам'ять: 16 ГБ RAM (рекомендовано 32 ГБ для продуктивного тестування)

  - Графічна карта: NVIDIA RTX 3060 / AMD Radeon RX 6700 або вище

  - Накопичувач: SSD 500 ГБ або більше

  - Операційна система: Windows 10/11 (64-bit)

**Програмне забезпечення**

  - Операційні системи та браузери:

  - Windows 10/11 (64-bit)

  - Microsoft Edge, Google Chrome, Mozilla Firefox (останні стабільні версії)

## **4. СПЕЦІАЛЬНІ ВИМОГИ**

:point_right: У цьому розділі вкажіть спеціальні вимоги до організації тестування, які не ввійшли в попередні пункти (це можуть бути вимоги стосовно пропускної здатності інтернет-каналу, хостингу тощо)

 **Спеціальні вимоги**

  Для забезпечення ефективного тестування необхідно враховувати додаткові вимоги до інфраструктури, мережевого середовища та доступу до ресурсів.

1. Мережеві вимоги
 - Пропускна здатність інтернет-каналу: мінімум 100 Мбіт/с, рекомендовано 1 Гбіт/с для роботи з віддаленими серверами.
 - Низька затримка в мережі: не більше 10 мс для точного тестування продуктивності та навантаження.
 - VPN-доступ: при тестуванні на захищених серверах або конфіденційних збірках проєкту.
2. Вимоги до серверів та хостингу
 - Виділені тестові сервери для навантажувального тестування з підтримкою високої продуктивності (не менше 32 ГБ RAM, процесор 16 ядер).
 - Хмарне середовище (AWS, Azure, Google Cloud) для автоматизації тестування та збереження логів.
 - Захист даних: шифрування переданих тестових даних (TLS 1.2/1.3) та контроль доступу за ролями.
3. Програмні вимоги
 - Ліцензії на інструменти тестування (TestComplete, Unreal Insights тощо) повинні бути активними протягом усього тестового періоду.
 - Оновлені драйвери відеокарт та бібліотеки DirectX/Vulkan для коректного тестування графічної продуктивності.
4. Логування та моніторинг
 - Автоматичний збір логів (Crash Reports, Performance Logs) під час тестування.
 - Моніторинг ресурсів (CPU, GPU, RAM) у реальному часі через спеціальні інструменти (Unreal Insights, RenderDoc).

## **5. ВЗАЄМОЗАЛЕЖНОСТІ**

:point_right: В цьому розділі наведіть існуючі взаємозв'язки між різними видами тестів (див. документ "[Методи тестування](../2.Planning/other/%D0%9C%D0%B5%D1%82%D0%BE%D0%B4%D0%B8%20%D1%82%D0%B5%D1%81%D1%82%D1%83%D0%B2%D0%B0%D0%BD%D0%BD%D1%8F.md)"). **У випадку, якщо порядок виконання тестів є істотним, вкажіть це тут і наведіть обгрунтування!**

 **Взаємозалежності між тестами**

   Різні види тестування вимагають певного порядку виконання для забезпечення коректності та ефективності тестового процесу. Взаємозв’язки між тестами виглядають наступним чином:

1. Юніт-тестування (Unreal Engine Automation Testing)
- Виконується першим, оскільки перевіряє окремі модулі на ранніх етапах розробки.
- Помилки, виявлені тут, можуть вплинути на подальше функціональне тестування.
2. Функціональне тестування (Gauntlet, TestComplete)
- Виконується після юніт-тестування для перевірки взаємодії модулів.
- Якщо юніт-тести виявили критичні помилки, функціональне тестування відкладається.
3. Тестування продуктивності (Unreal Insights, RenderDoc)
- Виконується після успішного проходження функціонального тестування.
- Якщо є значні функціональні помилки, тестування продуктивності може дати некоректні результати.
4. Навантажувальне тестування (Pix, UE Profiling Tools)
- Виконується після тестування продуктивності, щоб перевірити стабільність системи під навантаженням.
- Якщо продуктивність не відповідає вимогам, навантажувальне тестування не проводиться.
5. Тестування безпеки (GSVD)
- Виконується після всіх інших тестів, оскільки залежить від стабільності та коректної роботи системи.
- Якщо знайдені критичні проблеми, можуть знадобитися повторні функціональні або навантажувальні тести.

Порядок виконання тестів має критичне значення. Юніт-тестування виконується першим, оскільки впливає на всі інші етапи. Функціональне тестування передує продуктивному та навантажувальному тестуванню. Безпека перевіряється на фінальному етапі. Така послідовність забезпечує якість, ефективність та стабільність тестового процесу.
