## **3. СЕРЕДОВИЩЕ ТЕСТУВАННЯ**
 
   У цьому розділі описуються характеристики та конфігурація середовища тестування, включаючи апаратне та програмне забезпечення, необхідне для виконання тестів, а також інструменти для тестування та їхні налаштування.

**Апаратне забезпечення**

   Для коректного виконання тестів необхідні такі апаратні ресурси:

  - Процесор: Intel Core i7 / AMD Ryzen 7 або вище

  - Оперативна пам'ять: 16 ГБ RAM (рекомендовано 32 ГБ для продуктивного тестування)

  - Графічна карта: NVIDIA RTX 3060 / AMD Radeon RX 6700 або вище

  - Накопичувач: SSD 500 ГБ або більше

  - Операційна система: Windows 10/11 (64-bit)

**Програмне забезпечення**

  - Операційна система:

  - Windows 10/11 (64-bit)

   - Браузерне тестування: Використання Google Chrome, Mozilla Firefox та Microsoft Edge для тестування вебінтерфейсів, якщо застосовується.


## **4. СПЕЦІАЛЬНІ ВИМОГИ**

 Для забезпечення ефективного тестування необхідно враховувати додаткові вимоги до інфраструктури, мережевого середовища та доступу до ресурсів.

1. Мережеві вимоги
   - Пропускна здатність інтернет-каналу: мінімум 100 Мбіт/с, рекомендовано 1 Гбіт/с для роботи з віддаленими серверами.
   - Низька затримка в мережі: не більше 10 мс для точного тестування продуктивності та навантаження.

2. Вимоги до серверів та хостингу
   - Виділені тестові сервери для навантажувального тестування з підтримкою високої продуктивності (не менше 32 ГБ RAM, процесор 16 ядер).
   - Хмарне середовище (AWS, Azure, Google Cloud) для автоматизації тестування та збереження логів.
   - Захист даних: шифрування переданих тестових даних (TLS 1.2/1.3) та контроль доступу за ролями.

3. Програмні вимоги
   - Ліцензії на інструменти тестування (TestComplete, Unreal Insights тощо) повинні бути активними протягом усього тестового періоду.
   - Оновлені драйвери відеокарт та бібліотеки DirectX/Vulkan для коректного тестування графічної продуктивності.

4. Логування та моніторинг
   - Автоматичний збір логів (Crash Reports, Performance Logs) під час тестування.
   - Моніторинг ресурсів (CPU, GPU, RAM) у реальному часі через спеціальні інструменти (Unreal Insights, RenderDoc).

## **5. ВЗАЄМОЗАЛЕЖНОСТІ**

Різні види тестування вимагають певного порядку виконання для забезпечення коректності та ефективності тестового процесу. Взаємозв’язки між тестами виглядають наступним чином:

1. Юніт-тестування (Unreal Engine Automation Testing)
   - Виконується першим, оскільки перевіряє окремі модулі на ранніх етапах розробки.
   - Помилки, виявлені тут, можуть вплинути на подальше функціональне тестування.

2. Функціональне тестування (Gauntlet, TestComplete)
   - Виконується після юніт-тестування для перевірки взаємодії модулів.
   - Якщо юніт-тести виявили критичні помилки, функціональне тестування відкладається.

3. Тестування продуктивності (Unreal Insights, RenderDoc)
   - Виконується після успішного проходження функціонального тестування.
   - Якщо є значні функціональні помилки, тестування продуктивності може дати некоректні результати.

4. Навантажувальне тестування (Pix, UE Profiling Tools)
   - Виконується після тестування продуктивності, щоб перевірити стабільність системи під навантаженням.
   - Якщо продуктивність не відповідає вимогам, навантажувальне тестування не проводиться.

5. Тестування безпеки (GSVD)
   - Виконується після всіх інших тестів, оскільки залежить від стабільності та коректної роботи системи.
   - Якщо знайдені критичні проблеми, можуть знадобитися повторні функціональні або навантажувальні тести.

Порядок виконання тестів має критичне значення. Юніт-тестування виконується першим, оскільки впливає на всі інші етапи. Функціональне тестування передує продуктивному та навантажувальному тестуванню. Безпека перевіряється на фінальному етапі. Така послідовність забезпечує якість, ефективність та стабільність тестового процесу.


## **6. ТЕСТИ**

### **6.1. Тест 1 - Керування персонажем**

**Властивість: Реакція на натискання клавіш**

ОЧІКУВАНА ПОВЕДІНКА: Персонаж має рухатись вправо при натисканні D, вліво при натисканні A, та виконувати стрибок при натисканні Space без затримок чи пропусків введення.

ОЧІКУВАНА ШВИДКОДІЯ: Час відклику не повинен перевищувати 50 мс.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 99% натискань клавіш повинні викликати відповідну дію.

ЗАУВАЖЕННЯ: Особливу увагу приділити тестуванню одночасного натискання клавіш (наприклад, стрибок під час руху).

**Властивість: Фізика руху персонажа**

ОЧІКУВАНА ПОВЕДІНКА: Персонаж має реалістично прискорюватись, гальмувати та підкорятись гравітації. Стрибок має мати природну параболічну траєкторію.

ОЧІКУВАНА ШВИДКОДІЯ: Обчислення фізики не повинно знижувати частоту кадрів нижче 60 FPS.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: Рух має бути плавним у 95% випадків.

ЗАУВАЖЕННЯ: Перевірити поведінку при падінні з різних висот та приземленні на різні поверхні.

### **6.2. Тест 2 - Взаємодія з ігровим середовищем**

**Властивість: Виявлення колізій**

ОЧІКУВАНА ПОВЕДІНКА: Персонаж має коректно взаємодіяти з платформами, стінами та іншими перешкодами без проходження крізь них.

ОЧІКУВАНА ШВИДКОДІЯ: Обробка колізій не повинна перевищувати 10 мс.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 99% всіх колізій мають бути коректно опрацьовані.

ЗАУВАЖЕННЯ: Особливу увагу приділити кутовим випадкам, наприклад, коли персонаж стикається з кутом платформи.

**Властивість: Взаємодія з інтерактивними об'єктами**

ОЧІКУВАНА ПОВЕДІНКА: Персонаж повинен коректно взаємодіяти з предметами (підбирати їх, активувати і т.д.).

ОЧІКУВАНА ШВИДКОДІЯ: Час відгуку на взаємодію не повинен перевищувати 100 мс.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 98% всіх взаємодій мають працювати коректно.

ЗАУВАЖЕННЯ: Перевірити одночасну взаємодію з кількома об'єктами.

### **6.3. Тест 3 - Продуктивність**

**Властивість: Частота кадрів (FPS)**

ОЧІКУВАНА ПОВЕДІНКА: Гра має працювати із стабільною частотою кадрів як в простих, так і в насичених сценах.

ОЧІКУВАНА ШВИДКОДІЯ: Стабільний показник від 60 FPS на рекомендованих системах та не менше 30 FPS на мінімальних.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 95% часу гри має відповідати цільовому FPS.

ЗАУВАЖЕННЯ: Особливу увагу приділити сценам з багатьма рухомими об'єктами та ефектами.

**Властивість: Використання пам'яті**

ОЧІКУВАНА ПОВЕДІНКА: Гра не повинна мати витоків пам'яті чи надмірного використання ОЗП.

ОЧІКУВАНА ШВИДКОДІЯ: Приріст використання пам'яті не повинен перевищувати 5% протягом 1 години гри.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 100% ігрових сеансів не повинні завершуватися вичерпанням пам'яті.

ЗАУВАЖЕННЯ: Тестувати при тривалих ігрових сесіях (2+ години).

### **6.4. Тест 4 - Графічний інтерфейс та відображення**

**Властивість: Коректність відображення UI елементів**

ОЧІКУВАНА ПОВЕДІНКА: Всі елементи інтерфейсу мають відображатись коректно при різних роздільних здатностях.

ОЧІКУВАНА ШВИДКОДІЯ: Час рендерингу UI не повинен перевищувати 5 мс.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 100% елементів інтерфейсу мають відображатись без помилок.

ЗАУВАЖЕННЯ: Перевірити відображення на різних співвідношеннях сторін та роздільних здатностях.

**Властивість: Анімації персонажа та об'єктів**

ОЧІКУВАНА ПОВЕДІНКА: Всі анімації мають відтворюватись плавно та без артефактів.

ОЧІКУВАНА ШВИДКОДІЯ: Анімації не повинні призводити до падіння FPS нижче цільового.

ОЧІКУВАНА ДОСТОВІРНІСТЬ: 98% анімацій мають відтворюватись коректно.

ЗАУВАЖЕННЯ: Перевірити коректність переходів між різними анімаціями та їх синхронізацію з діями гравця.
